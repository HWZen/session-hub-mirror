# 0.23.0 — Session Hub 公开作品集准备

## 目标

将 Session Hub 整理为能够展示工程能力、支持读者与 AI Agent 自行安装使用的 MIT 开源项目。优先公开原仓库并保留提交历史；根据隐私审查结果决定历史处理方式。

项目起因：多台机器、多个 Agent/harness 的会话彼此隔离，缺少跨端消息聚合与检索。作者尝试 OpenViking 后认为其偏向个人数据管理，且会话向量索引在自己的环境中资源需求与检索效果未达预期，因此构建专注于会话消息的平台。README 将其表述为作者的选型体验，而非通用性能结论。

核心用法：

- “昨天我在 A 电脑的某 Agent 上装了某 skill，你现在在 B 电脑上也装一下”：按时间、机器和 Agent 过滤，检索会话片段，再读取完整记录，由当前 Agent 执行安装。
- “总结今日”：查询当天跨机器、跨 Agent 的会话记录，由消费端 Agent 汇总。

归档平台负责保存与检索，安装和总结由消费端执行。

## 方案

### 1. 隐私审查与公开方式决策

审查对象包括所有本地及 GitHub 可见分支、标签可达的 Git 历史、当前文件、提交消息与作者元数据，以及 GitHub Releases、附件、Actions 日志、仓库描述等公开后可见资产。服务器 SSH remote 不作为本次同步或部署对象。

分类检查：

- 真实密钥、token、凭证、带凭证 URL。
- 会话正文、工具输入输出、截图、日志、数据库、备份、测试及验收原始记录。
- 个人与公司信息、邮箱、个人路径、主机名、域名、IP、端口、服务器运维细节。
- 区分模拟数据、通用源文件路径、第三方公开 API 地址与真实私人信息，避免误删有效技术说明。

优先使用可信的本地 secret scanner 并补充人工上下文审查。扫描结果仅保留类别、文件路径、提交定位与建议；不输出密钥或会话正文，不将未经脱敏的报告提交或上传外部服务。历史大文件分批处理，不能以仅扫描 HEAD 代替全历史审查。

发现疑似真实凭证时，先向用户报告位置、影响范围和处置建议。轮换、作废、Git 历史重写、强制推送均须另行获得用户确认；不能通过普通删除提交声称历史泄露已解决。

根据审查结果提出原仓库公开或建立脱敏仓库的建议。历史重写前明确备份、受影响分支与标签、协作者重新同步以及远端历史残留风险。

### 2. 合并已完成插件

先审查两条分支的新增内容，再在当前工作分支整合 Codex 和 OpenCode 实现。保留各插件既有版本号，核对根脚本、workspace、锁文件与全局文档冲突。合并内容同样纳入最终隐私审查。

### 3. MIT 许可证

新增根 `LICENSE`，采用标准 MIT 文本。版权年份为 2026，署名在实施时向用户确认；需要时同步包级许可证元数据，保持包的发布策略。

### 4. README 与安装文档

README 包含动机、两个核心工作流、架构、实际支持的来源、工程亮点、安装配置、使用入口、安全边界和当前限制。

技术亮点以实际实现为依据：源时间戳与幂等键、全量 raw 与检索内容分离、reasoning 归一化、切片索引、混合检索、模型分表与同模型故障切换、非阻塞上传和 SQLite 连接约束。区分已实现功能与实验或计划功能。

服务端说明至少覆盖 Node/npm 前置要求、原生依赖条件、依赖安装、环境变量、数据库路径、启动方式、前端、embedding provider 配置、鉴权、健康检查和 API 帮助。私人部署手册改为可复用的自托管说明；本机运维资料若需保留，应存于仓库之外。

逐一核对 OpenCode、ZCode、Hermes、DSH、Claude Code、Codex、WorkBuddy 的实际安装脚本与配置行为。按来源列明前置依赖、安装命令、配置优先级、启用方式、重启要求、历史回填、日志和删除同步能力。复杂说明可拆为子系统文档，由根 README 提供明确入口。

核对 Agent Skill 的安装路径和连接信息来源。所有示例使用明确占位符或本地示例地址，不引导读者访问作者的生产实例。

验收以仓库可读性与文档对应实现的静态核对为主；测试或构建结果只在实际执行后记载，不把文档核对描述成已验证从零安装。

### 5. 决策与公开

根 `plan.md` 已在规划阶段更新公开方向。实施时同步隐私处理后的架构与运维说明，并维护相关 AGENTS.md 和 Skill 的一致性。

公开前提供最终审查摘要、历史处理情况、文档覆盖情况与阻塞项。满足条件后将选定仓库改为 public，并读取实际可见性复核；存在未处理的敏感内容时不得公开。所有任务相关提交按仓库规范使用中文提交信息。

## 验收标准

1. 每项扫描发现都有分类、处置或用户确认记录；没有未处理的真实凭证或私人会话进入公开资产。
2. 用户在凭证轮换、历史重写和强制推送前获知影响并明确确认。
3. Codex 与 OpenCode 已完成实现进入展示版本，脚本与 workspace 配置完整。
4. 根 LICENSE 为标准 MIT 文本，署名准确。
5. AI Agent 可从 README 及其链接找到服务端、各插件、采集器与 Skill 的完整安装配置步骤，无需访问作者的私有环境。
6. README 准确说明两个核心用法和平台/消费端职责，实际支持状态与实现一致。
7. 原有不相关 worktree 的改动不被覆盖；测试和运行验收记录与实际执行一致。
8. 目标仓库公开后可见性确认成功，公开资产与最终审查范围一致。
